# Art provenance — updated 2026-11-09

## Campaign additions — 2026-11-09

The built-in **imagegen** tool generated five environment backgrounds, one isolated transparent outpost base and one repeatable dirt-road texture in `Assets/Art/Campaign`. The user's `Assets/Art/Weapons/bow.png` was supplied as a style reference, not as an image to overwrite. Original source files remain. The exact seven prompts are saved in [GENERATION_PROMPTS.json](../Assets/Art/Campaign/GENERATION_PROMPTS.json).

Names: `ForestClearing.png`, `TwilightCrossing.png`, `AncientGarden.png`, `AmberQuarry.png`, `MoonlitSanctuary.png`, `OutpostBase.png`, `RoadTexture.png`. Backgrounds deliberately omit roads, towers, enemies and UI: Unity renders route geometry from the same waypoint data used by movement and placement. Base uses alpha and is fitted to its actual contact footprint. The road texture is imported as repeatable; no raster image was manually repainted by code. Small shot/hit/base/blast effects use Unity shapes and tint, with no new sound or external effect assets.

These are AI-assisted project assets, not asserted student-painted originals. The style reference source's authorship/license is still unspecified as recorded below.

## Original beta integration

The user supplied the six source images under `Assets/Art/Enemies` and `Assets/Art/Weapons`. Their original authors/licenses are not specified in this workspace; this record does not assert authorship or ownership of those originals.

The built-in **imagegen** tool created six transparent-background derivatives, now stored in `Assets/Art/Sprites`. Originals were preserved. These are AI-assisted extractions and may differ in fine details; they are not pixel-exact masks. That initial integration did not generate environment art or animation frames; environment additions are recorded above. Original image perspective/style was retained as far as practical.

All prompts used `transparent_background: true` and each corresponding local source as the edit target.

| Sprite | Extraction instruction |
| --- | --- |
| ThornBow | Extract only the thorn crossbow tower including round stone platform, wood supports, bolt quiver and attached lanterns. Remove all forest, ground, trees and scenery. Preserve painted object, colors, shape, view, proportions and details. |
| DustCannon | Extract only the dust cannon tower including barrel, fire chamber, supports, banner and round stone foundation. Remove forest, landscape, dirt ground, outside smoke and trees. Keep object details and perspective. |
| WireTrap | Extract only four metal-capped posts, crossed wood supports and wire mesh. Remove surrounding ground, forest, trees, scenery and unattached grass. Preserve original design and perspective. |
| Runner | Remove white background from dark round enemy with orange eyes; preserve shape, shading, black outline and colors. |
| RetreatWisp | Remove baked gray/white checkerboard; keep purple ghost, face, hands and smoke aura with soft alpha edges; preserve pose and colors. |
| IronGuard | Remove white background from armored stone golem with gold runes and red eyes; preserve limbs, armor and pixelated appearance. |

Common constraints: one centered object, entire object visible, small clear padding, actual alpha transparency, no redesign, extra objects, text, border, new backdrop or external cast shadow. Bow requested small padding; the remaining five requested 4% padding explicitly. Output canvas padding was handled by Unity Sprite rectangle trimming, not by rewriting PNG pixels.

Sprite import settings and trimmed rectangles are generated by `Assets/Editor/DodgeLine/SpriteImportUtility.cs`, called by CampaignBuilder when creating missing art data. Visual sizes/offsets are editable in `Assets/Data/GameArt.asset` (GameArtSet). Both the original source assets and these generated derivatives remain with their Unity `.meta` files. During cleanup the runtime sprites were moved through AssetDatabase, preserving references; no new image was generated in that cleanup.
